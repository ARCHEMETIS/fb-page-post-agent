## สิ่งที่หาเจอเองแล้ว

- เช็ค commit history ของ luiquest repo แล้ว ไม่มี commit ไหนพูดถึงโควตา LLM, rate limit,
  หรือปัญหาตอนคนใช้เยอะขึ้นโดยตรง เจอแต่ "Cap XP per user per day" (1e60cec, 5 ส.ค. 2026)
  ซึ่งเป็นเรื่องกันโกง XP ในเกม ไม่เกี่ยวกับโควตา API
- เช็คไฟล์ README ของ repo แล้ว ยืนยันข้อเท็จจริงทางเทคนิคครบ:
  - แอปใช้ Google Gemini free tier ทำ AI coach (ให้คำใบ้/คำอธิบายตอนติด)
  - โควตานับที่ระดับโปรเจกต์ ไม่ใช่ต่อผู้ใช้ — ถ้าไม่ระวัง คนใช้เยอะขึ้นเมื่อไหร่ โควตาก็หมดไวขึ้นเท่านั้น
    ไม่ว่าใครจะใช้เท่าไหร่ก็แชร์โควตาก้อนเดียวกันหมด

    (2) จำกัด rate ต่อผู้ใช้ ไม่ให้คนใดคนหนึ่งใช้โควสรวมหมดคนเดียว
  - เอาไปเขียนเป็นโพสต์สายเดฟได้เลยโดยไม่ต้องถามเพิ่มในส่วนนี้
- ที่ยังไม่มีคือเรื่องราวส่วนตัว — author-notes.md ระบุไว้แล้วว่า "ตอนเจอปัญหาโควตา LLม ต่อโปรเจกต์
  ผมรู้ตัวตอนไหน แล้วแก้ยังไง" เป็นเรื่องที่ยังไม่ได้เล่า และนี่คือฉากเปิดที่โพสต์นี้ต้องการ
  (กฎการเขียน: เปิดโพสต์ด้วยฉากจริงที่เกิดขึ้นจริง ห้ามแต่งฉากแทนพี่)

## คำถาม

1. ตอนรู้ตัวว่าโควตา LLM มันนับรวมทั้งโปรเจกต์ไม่ใช่ต่อคน รู้ตัวตอนไหน — กำลังทำอะไรอยู่ตอนนั้น
   เจอด้วยตัวเอง (เช่น เห็น error หรือโควตาใกล้หมด) หรือรู้ล่วงหน้าตั้งแต่อ่านเอกสารก่อนเขียนโค้ด
2. ตอนนั้นรู้สึกยังไง ตกใจไหม กังวลว่าแอปจะพังตอนมีคนใช้เยอะขึ้นไหม
3. ก่อนจะมาลงเอยที่วิธีแคช roadmap + จำกัด rate ต่อผู้ใช้ เคยลองวิธีอื่นมาก่อนไหม
   หรือคิดออกตั้งแต่แรกเลย
4. ตอนนี้มีเหตุการณ์จริงที่โควตาใกล้หมดหรือหมดจริงๆ แล้วบ้างหรือยัง (ตอนนี้มีผู้ใช้แค่พี่คนเดียว
   เป็นการเตรียมรับมือล่วงหน้า หรือเจอปัญหาจริงมาแล้ว)

ตอบสั้นๆ พอครับ ไม่ต้องเรียบเรียง — เอาไปเขียนเป็นโพสต์เอง
